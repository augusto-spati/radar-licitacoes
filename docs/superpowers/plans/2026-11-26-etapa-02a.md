# Radar de licitações: plano 2a (API local + protótipo do front)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar uma API JSON local (FastAPI) e o front da v1 em React + Astryx, com dados de exemplo tirados de editais reais e um contrato que impede a IA de duplicar componentes ou mexer na navegação. O protótipo sai como link navegável para o Augusto revisar no celular.

**Architecture:** `radar.api` é uma nova porta de entrada, ao lado da `cli`, e usa só o que `coleta` e `editais` expõem publicamente. Os modelos Pydantic da API definem o contrato JSON. O exportador de exemplo usa esses mesmos modelos, então o fixture do front tem o mesmo formato da API, e os tipos TypeScript são gerados do OpenAPI. O front fica em `frontend/`, é uma SPA com HashRouter e lê os dados por uma "fonte" trocável (exemplo ou API).

**Tech Stack:**
- **Backend:** FastAPI, uvicorn, pydantic v2.
- **Front:** React 19, Vite, TypeScript, Astryx 0.7.17 (`@astryxdesign/core`, `@astryxdesign/theme-neutral`, `@astryxdesign/cli`) com StyleX, react-router (HashRouter), openapi-typescript.
- **Testes:** Vitest e Testing Library no front, Playwright para o navegador.
- **Qualidade:** ESLint com `eslint-plugin-boundaries`, e jscpd.

**Spec:** `docs/superpowers/specs/2026-11-26-etapa-02-design.md` (contexto em `2026-11-26-radar-design.md`).

## Global Constraints

- O Astryx tem versão travada exata (`0.7.17`, sem `^` nem `~`), igual em core, tema e cli. Toda página parte de um template do Astryx (`astryx build` → `astryx template`). Sem `<div>`/`<span>` soltos, sem CSS importado e sem cor ou medida fixa no código fora de `src/componentes/base/`.
- O front usa **HashRouter**, e o build usa `base: './'` (hospedagem estática: artefato agora, S3/CloudFront depois).
- As rotas da v1 formam uma lista fechada: `/` (lista), `/edital/:id` (detalhe), `/entrar` (login visual, sem autenticação nesta etapa). Elas ficam num arquivo único, `frontend/src/rotas.tsx`, que também alimenta a navegação.
- O texto da interface é em pt-BR. As datas aparecem como `dd/mm` ou `dd/mm/aaaa HH:MM` no horário de Brasília, e os valores em `R$` com `Intl.NumberFormat('pt-BR')`.
- A API é só leitura e fica sob o prefixo `/api`. Datas saem em ISO 8601 sem fuso (horário de Brasília), exceto `atualizado_em`, que sai em ISO 8601 com fuso. Valores monetários saem como string decimal (`"1369661.52"`) ou `null`.
- Um edital está "desatualizado" quando `agora − atualizado_em > 36 h`, ou quando `atualizado_em` é `null`.
- Nomes das modalidades: `4` Concorrência eletrônica, `5` Concorrência presencial, `6` Pregão eletrônico, `7` Pregão presencial.
- Fronteiras:
  - `radar.api` importa só `radar.comum`, `radar.coleta` e `radar.editais` pelos pacotes raiz, nunca submódulos;
  - nenhum módulo importa `radar.api`;
  - o contrato `forbidden` do import-linter passa a incluir `radar.api`.
- Os screenshots de referência do Playwright são gerados só em Linux (CI ou o container `mcr.microsoft.com/playwright`), nunca no Windows.
